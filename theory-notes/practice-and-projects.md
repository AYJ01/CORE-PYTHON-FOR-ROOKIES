# Practice and Projects: turn ideas into skills

Reading helps you recognize an idea. Writing code helps you learn to use it. Start with a project that feels small enough to finish. You can decorate or expand it after the basic version works.

## Tiny projects, in a helpful order

1. **Friendly greeter** — use `input()` and `print()` to ask for a name and say hello. Folder: `getting-started/`.
2. **Score keeper** — store a score in a variable, add points, and display it. Folders: `variables/`, `operators/`.
3. **Number guessing game** — use a secret number, comparisons, `if`, and a loop. Folders: `variables/`, `conditional-statements/`, `iterators/`.
4. **Word helper** — count letters, make text uppercase, or check whether a word is a palindrome. Folders: `strings/`, `functions/`.
5. **Shopping list** — add, show, and remove items. Folders: `collections/`, `functions/`, `conditional-statements/`.
6. **Quiz** — ask several questions, check answers, and keep score. Folders: `collections/`, `iterators/`, `functions/`.
7. **Safe notes file** — save and load simple text or JSON data. Folders: `file-handling/`, `exception-handling/`.
8. **Tested calculator** — write a few calculation functions and tests that check easy and tricky cases. Folders: `functions/`, `testing/`.
9. **Contact book** — store names in SQLite, then add, find, update, and remove contacts. Folders: `collections/`, `databases/`, `exception-handling/`.
10. **Small API reader** — request public information from a service and display a few fields. Folders: `networking/`, `exception-handling/`. Ask a trusted adult before using an unfamiliar website; never put private keys or passwords in your code.

## A project-building recipe

1. **Describe the goal in one sentence.** Example: “The program asks a question and tells me whether my answer is right.”
2. **Break it into tiny steps.** Ask, store, compare, respond.
3. **Make the simplest version work.** Do not add a menu, colors, or extra features yet.
4. **Try normal and unusual inputs.** What if the person enters nothing, a word, or a very large number?
5. **Fix one issue at a time.** Use the error message and print small clues to see what the program is doing.
6. **Add tests or save data** when the project is ready for those ideas.
7. **Write a short README** saying what the project does and how to run it.

## How to tell you are learning

You are making progress when you can explain what a line does, predict an example's result, find a topic again, and change a program without being afraid of trying. You do not have to memorize every Python feature. Keep practicing, make things you enjoy, and ask questions when you need help.
